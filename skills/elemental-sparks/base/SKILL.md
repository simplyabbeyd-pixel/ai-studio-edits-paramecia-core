# Elemental Spark Base

## Purpose
Keep elemental exploration scientifically grounded, recursively recoverable, and separable from Paramecia metaphor.

## Required identity header
Every generated elemental table or skill must include:

- Atomic number
- Element
- Symbol
- Group
- Period
- Block

## Scientific-method loop
1. **Observe** — state the physical/chemical behavior in a specific system.
2. **Question** — what exact function is being performed?
3. **Hypothesize** — propose the smallest rule that might explain that function.
4. **Test** — vary one parameter at a time.
5. **Record** — success, failure, limits, assistance, compatibility.
6. **Reduce** — rewrite the result as a pure function with explicit inputs and outputs.
7. **Metaphorize last** — only after the scientific layer is stable.

## Smallest rediscoverable base
If scale becomes confusing, return to:

`IDENTITY -> FUNCTION -> INPUTS -> OUTPUT -> PARAMETERS -> LIMITS -> COMPATIBILITY -> ASSISTANCE`

The base must be understandable without world lore, agent personality, or prior metaphor.

## Compatibility result
Every interaction resolves to one of:

- `DIRECT` — the element/material can perform the requested function with the target under the specified conditions.
- `ASSIST` — the function is plausible, but another material/process/interface is required.
- `LIMITED` — the function works only within explicit constraints.
- `NO_MATCH` — the requested function is not supported by the scientific behavior being modeled.
- `UNKNOWN` — evidence is insufficient.

## Rules
- Scientific facts and metaphors live in separate fields.
- Do not treat an elemental metaphor as an intrinsic personality or moral quality.
- Do not call a metaphor a force, particle, law, or chemical property.
- Assistance is not failure; it is part of the interaction map.
- Prefer a small accurate rule over a large poetic one.
- Preserve uncertainty and source provenance.
